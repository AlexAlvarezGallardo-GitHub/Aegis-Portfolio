Aegis uses a **spec-first** approach: every API is defined as an **OpenAPI 3 contract** before any code is written. Contracts live in `specs/<feature>/contracts/` and drive both implementation and client generation.

## Conventions

- Base path: `/api/v1`
- REST over HTTP — JSON request/response bodies
- UUID identifiers (v7) for resources
- Standard error envelope returned from `@RestControllerAdvice`
- Pagination for list endpoints

## Domain events

Events are versioned JSON Schema contracts published to Kafka:

| Event | Topic |
|-------|-------|
| `UserRegistered` | `aegis.identity.user.registered` |
| `UserAuthenticated` | `aegis.identity.user.authenticated` |
| `UserAccountLocked` | `aegis.identity.user.account.locked` |
| `WalletCreated` | `aegis.wallet.wallet.created` |
| `FundsDeposited` | `aegis.wallet.funds.deposited` |
| `WalletBalanceAdjusted` | `aegis.wallet.wallet.balance.adjusted` |
| `FraudAssessmentCompleted` | `aegis.fraud.assessment.completed` |

Contracts are versioned with an explicit `schemaVersion` field so consumers evolve safely.
